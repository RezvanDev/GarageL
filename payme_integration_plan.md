# План реализации — Интеграция Payme Merchant API

Этот план описывает шаги, необходимые для интеграции **Payme (Paycom) Merchant API** для приема онлайн-платежей (как за сам товар, так и за его доставку) на платформе Garage.

---

## Требуется согласование с пользователем

> [!IMPORTANT]
> **Настройки мерчанта в кабинете Payme Business:**
> Для создания кассы (web checkout) в панели Payme предоставьте им следующие параметры:
> - **EndpointURL**: `https://nexaicall.space/api/v1/payment/payme` (или ваш рабочий домен)
> - **Параметр аккаунта (Идентификатор чека)**: `order_id` (используется для сопоставления платежа с конкретным заказом).
> 
> Также вам потребуется добавить следующие переменные окружения в файл `.env` на сервере:
> - `PAYME_KEY` (Секретный ключ мерчанта, выдается в кабинете Payme, используется для Basic Auth).
> - `PAYME_MERCHANT_ID` (ID вашего мерчанта, нужен для генерации платежных ссылок).
> - `PAYME_SANDBOX` (Установите `true` или `false` для переключения между тестовой средой `test.paycom.uz` и рабочей `checkout.paycom.uz`).

## Предлагаемые изменения

### 1. Схема базы данных

Нам нужна отдельная таблица для логирования транзакций и их статусов, как требует протокол Payme для предотвращения повторных списаний и разбора спорных ситуаций.

#### Скрипт миграции `migrate_payme.js`
Скрипт создает таблицу `payme_transactions`:
```sql
CREATE TABLE IF NOT EXISTS payme_transactions (
    id VARCHAR(255) PRIMARY KEY,       -- ID транзакции в системе Payme (24-значный hex)
    time BIGINT NOT NULL,              -- Время создания транзакции в Payme (timestamp ms)
    state INTEGER NOT NULL,            -- Состояние: 1 = создана, 2 = проведена, -1 = отменена, -2 = отменена после проведения (возврат)
    amount BIGINT NOT NULL,            -- Сумма в тийинах (копейках)
    order_id INTEGER REFERENCES orders(id),
    create_time BIGINT NOT NULL,       -- Время создания в нашей БД (ms)
    perform_time BIGINT,               -- Время проведения в нашей БД (ms)
    cancel_time BIGINT,                -- Время отмены в нашей БД (ms)
    reason INTEGER                     -- Код причины отмены
);
```

---

### 2. Сервисы бэкенда (API)

#### Контроллер `paymeController.js`
Реализовать обработчик протокола JSON-RPC 2.0 со следующими методами:
- **Авторизация**: Валидация заголовка `Authorization: Basic <base64(payme:PAYME_KEY)>`.
- **CheckPerformTransaction**: Проверка существования заказа, его готовности к оплате (статус `offer_selected` или `waiting_delivery_payment`) и точного совпадения суммы (переводится в тийины).
- **CreateTransaction**: Запись транзакции в таблицу со статусом `1`. Проверка на наличие уже запущенных транзакций для этого заказа.
- **PerformTransaction**: Смена статуса транзакции на `2` и фиксация времени. Смена статуса заказа:
  - Если оплачивался товар (`offer_selected`) -> меняем на `paid_product` (с отправкой уведомлений в Telegram).
  - Если оплачивалась доставка (`waiting_delivery_payment`) -> меняем на `delivery_paid` (с уведомлением логистов).
- **CancelTransaction**: Отмена транзакции (статусы `-1` или `-2`). Отмена допускается только если заказ еще не был отправлен/обработан дальше по цепочке.
- **CheckTransaction**: Возврат детальной информации о времени создания, проведения и отмены конкретной транзакции.

#### Роутер `paymentRoutes.js`
Добавить маршруты оплаты:
- `POST /api/v1/payment/payme` — для обработки запросов от серверов Payme.

#### Обновление маршрутов заказов `orderRoutes.js`
Добавить маршрут для получения платежной ссылки клиентом:
- `GET /orders/:id/payment-link`

#### Обновление контроллера заказов `orderController.js`
- Реализовать метод `getPaymentLink`:
  - Проверяет права доступа клиента к заказу.
  - Определяет сумму к оплате (стоимость товара, если статус `offer_selected`, либо стоимость доставки, если статус `waiting_delivery_payment`).
  - Формирует строку параметров для GET-запроса Payme:
    `m=MERCHANT_ID;ac.order_id=ORDER_ID;a=AMOUNT_IN_TIYINS;l=LANG;c=RETURN_URL;ct=REDIRECT_TIMEOUT;cr=CURRENCY_CODE`
    - `m`: ID мерчанта (из переменной окружения `PAYME_MERCHANT_ID`).
    - `ac.order_id`: Код заказа (передаем `order.id`).
    - `a`: Сумма платежа в тийинах (сумма заказа или доставки, умноженная на 100).
    - `l`: Язык (по умолчанию `ru`).
    - `c`: URL для возврата пользователя после оплаты (ссылка на личный кабинет клиента, например, `https://nexaicall.space/orders`).
    - `ct`: Время задержки перед возвратом в миллисекундах (например, `5000`).
    - `cr`: Код валюты UZS в ISO формате (передаем `860`).
  - Кодирует всю сформированную строку в Base64.
  - Возвращает итоговую ссылку вида `https://checkout.paycom.uz/<base64_string>` (или `https://test.paycom.uz/<base64_string>` в режиме песочницы).

#### Подключение в `server.js`
- Подключить `paymentRoutes` на префикс `/api/v1/payment`.

## План тестирования и проверки

### Автоматизированная проверка
- Выполнить миграцию для создания таблицы: `node migrate_payme.js`.
- Написать скрипт авто-тестирования `scratch/mock_payme_test.js`, который симулирует RPC-запросы от Payme (`CheckPerformTransaction`, `CreateTransaction`, `PerformTransaction`) и проверяет корректность переключения статусов заказов в БД.

### Ручная проверка
- Перевести тестовый заказ в статус `offer_selected`.
- Нажать кнопку оплаты в кабинете клиента и убедиться в переходе на правильный URL-адрес Payme (Sandbox).
- Отправить POST-запрос с симуляцией успешной оплаты и убедиться, что статус заказа обновился до `paid_product`.
